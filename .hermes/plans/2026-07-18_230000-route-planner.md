# Route Planner Feature — Implementation Plan

> **For Hermes:** Use subagent-driven-development skill to implement this plan task-by-task.

**Goal:** Add a route planning modal that uses OpenRouteService's wheelchair profile to plan accessible routes between two locations: "My Location" (GPS) or any place from the existing search.

**Architecture:** Extract the search bar + results list from SearchModal into a reusable `PlaceSearch` component. Build a new `RoutePlannerModal` with two PlaceSearch fields (from/to) and a "Plan Route" button. Use OpenRouteService v2 Directions API (wheelchair profile) to compute route geometry, then render it as a LineLayer on the MapLibre map. A simple route summary card shows distance and duration.

**Tech Stack:** React Native, MapLibre GL JS, Expo Location, OpenRouteService API v2 (free tier, requires API key)

**API Endpoint:** `GET https://api.openrouteservice.org/v2/directions/wheelchair/geojson`
- Coordinates: `lng1,lat1|lng2,lat2` (semicolon-separated)
- Free tier: 500 requests/day, 40 req/min
- Signup at https://openrouteservice.org/dev/#/signup

---

## Research Notes

### Why OpenRouteService
- **Dedicated wheelchair profile** — routes only on wheelchair-accessible ways (sidewalks, pedestrian paths, roads marked wheelchair=yes in OSM)
- **Open source, free tier** (500 req/day, 40/min)
- **Covers Norway** — uses global OpenStreetMap data
- **GeoJSON output** — easy to render on MapLibre
- **No vendor lock-in** — OSM-based, can self-host if needed

### Alternatives ruled out
- **OSRM demo server** (`router.project-osrm.org`) — only driving profile, no wheelchair support, not for production use
- **GraphHopper free tier** — only car/bike/foot, no wheelchair
- **Google Directions** — requires API key + billing, proprietary, no wheelchair-specific profile
- **Mapbox Directions** — requires API key + billing, walking-only profile

### Coordinate format
ORS uses `longitude,latitude` (lng,lat) — same as MapLibre and our existing PlaceResult format. No axis flip needed.

### Task 3: Add route-fetching utility to map-api

**Objective:** Create `fetchRoute()` function that calls OpenRouteService and returns GeoJSON

**Files:**
- Modify: `mobile/src/utils/map-api.ts`
- Create/modify: `mobile/src/constants/map-config.ts` (add ORS_API_URL constant)

**New function:**
```ts
// ── Route planning (OpenRouteService) ──────────────────────────────────

export interface RouteResult {
  /** GeoJSON FeatureCollection with LineString geometry */
  geojson: any;
  /** Distance in meters */
  distance: number;
  /** Duration in seconds */
  duration: number;
  /** Human-readable distance (e.g. "1.2 km") */
  distanceLabel: string;
  /** Human-readable duration (e.g. "18 min") */
  durationLabel: string;
}

export async function fetchRoute(
  from: [number, number],  // [lng, lat]
  to: [number, number],    // [lng, lat]
  apiKey: string,
): Promise<RouteResult> {
  const coords = `${from[0]},${from[1]}|${to[0]},${to[1]}`;
  const url = `${ORS_API_URL}/v2/directions/wheelchair/geojson?api_key=${encodeURIComponent(apiKey)}&start=${coords}`;
  
  const res = await fetch(url);
  if (!res.ok) throw new Error(`Route API error: HTTP ${res.status}`);
  
  const geojson = await res.json();
  const props = geojson.features?.[0]?.properties?.summary;
  const distance = props?.distance ?? 0;
  const duration = props?.duration ?? 0;

  return {
    geojson,
    distance,
    duration,
    distanceLabel: distance >= 1000
      ? `${(distance / 1000).toFixed(1)} km`
      : `${Math.round(distance)} m`,
    durationLabel: duration >= 3600
      ? `${Math.floor(duration / 3600)} t ${Math.round((duration % 3600) / 60)} min`
      : `${Math.round(duration / 60)} min`,
  };
}
```

**Add to map-config:**
```ts
export const ORS_API_URL = 'https://api.openrouteservice.org';
```

  <MapLibreGL.ShapeSource
    id="route-source"
    shape={routeGeojson}

    <MapLibreGL.LineLayer
      id="route-line"
      style={{
        lineColor: '#ecaa30',        // amber (accent color)
        lineWidth: 4,
        lineOpacity: 0.85,

        lineColor: '#0d1117',

)}

## Open Questions / Risks

1. **ORS API key management** — Currently stored as a constant in map-config. For production, consider environment variable or secure storage. But for MVP, plain constant is fine.
2. **ORS free tier limits** — 500 req/day is generous for an accessibility app. If exceeded, shows friendly error.
3. **MapLibre GeoJSON rendering** — `ShapeSource` requires the GeoJSON object, not a URL. The ORS geojson endpoint returns a full FeatureCollection — perfect for this.
4. **Route clearing** — When modal closes, should the route stay visible? Recommend clearing it so the map returns to clean state.
5. **Route fit-to-bounds** — Currently planned but may be deferred to a follow-up if MapLibre RN's `fitBounds` API is tricky.
